# H-18: Session Cookies Lack the Secure Flag

- **Issue:** H-18 — admin and patient cookies lack `Secure` (cookie part only)
- **Severity:** High

## Root cause

Admin session cookies and the patient session cookie were issued with `httponly` and `samesite` but no `secure` attribute. Browsers could therefore send session cookies over plain HTTP.

## Fix

Added `COOKIE_SECURE` to `app/config.py`, defaulting to true. It accepts `COOKIE_SECURE=false` (or `0`, `no`, `off`) for local development.

Applied `secure=settings.COOKIE_SECURE` alongside `httponly=True` and `samesite="lax"` to:

- Admin signup cookie (`app/main.py`)
- Admin login cookie (`app/main.py`)
- Admin logout deletion (`app/main.py`)
- Patient session cookie (`app/chat.py`)

`app/auth.py` contains no cookie-setting call; its session value creation, decoding, lifetime, and lack of revocation were left unchanged.

## Files changed

- `app/config.py`

## Tests

`tests/test_cookie_security.py` calls the real cookie-issuing code with fake database connections and a minimal fake settings object. It verifies:

- Patient cookies contain `Secure`, `HttpOnly`, and `SameSite=lax`.
- Setting `COOKIE_SECURE` false removes only `Secure` for local development.
- Admin login cookies contain all three flags.
- Logout deletion preserves the same flags.
