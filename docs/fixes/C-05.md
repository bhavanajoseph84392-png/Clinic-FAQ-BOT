# C-05: Tenant Context Set With a Bind Parameter

## What was wrong

`app/db.py` set the row-level-security tenant value with:

```sql
SET LOCAL app.clinic_id = %s;
```

PostgreSQL does not accept bind parameters in `SET` statements; the placeholder is sent to the server as literal SQL.

## Verified error

Running the statement against the Neon scratch branch failed with:

```text
syntax error at or near "$1"
```

## What changed

`app/db.py` now uses the parameterized function form:

```python
cur.execute("SELECT set_config('app.clinic_id', %s, true);", (str(clinic_id),))
```

The third argument `true` makes the setting local to the current transaction, matching `SET LOCAL`. The call remains inside the existing transaction, so tenant isolation behavior is unchanged.

## Test

`tests/test_db_tenant.py` injects a fake pool and cursor, records the executed SQL and parameters, and asserts that the SQL contains `set_config`, that the clinic id is passed as a bound parameter, and that the old `SET LOCAL app.clinic_id` text is absent. No database connection is used.
