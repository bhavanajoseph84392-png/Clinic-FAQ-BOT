# C-09: Demo Seed Overwrites Admin Passwords and Runs Against Non-Local Databases

- **Issue:** C-09 — unsafe demo seed credentials, admin password overwrite, weak local-host guard
- **Severity:** Critical

## Root cause

The demo seed's admin upserts used `ON CONFLICT (email) DO UPDATE SET password_hash = EXCLUDED.password_hash`, so re-running the seed replaced an existing administrator's password. The seed also had no check that the target database was local, so a production connection could be seeded accidentally.

Environment-variable loading for `DEMO_ADMIN_PASSWORD` and `DEMO_WEBHOOK_SECRET` was already present from C-03; it remains unchanged and still exits with a clear message when either variable is missing.

## Fix

- Added `database_is_local`, which accepts only `localhost`, `127.0.0.1`, or `::1` as the parsed `DATABASE_URL` host.
- `seed_demo_data` now exits with status 1 before any database call when the host is not clearly local.
- Both admin inserts now use `ON CONFLICT (email) DO NOTHING`, so existing password hashes are never overwritten.

## Tests

`tests/test_seed_demo_safety.py` loads the seed script directly and uses fake database connections; no database or network service is contacted. It verifies:

- A non-local or unparseable `DATABASE_URL` exits with status 1 before `get_db` is called.
- Both admin inserts use `DO NOTHING` and do not update `password_hash`.
