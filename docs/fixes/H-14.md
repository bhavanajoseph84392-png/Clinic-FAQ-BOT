# H-14: Patient Values Injected Unescaped Into HTML Emails

- **Issue:** H-14 — HTML injection into clinic and patient emails
- **Severity:** High

## Root cause

Patient-controlled values were interpolated directly into HTML email bodies. A patient name, email, question, or admin reply containing markup would be rendered as active HTML in emails sent under the clinic's name.

## Fix

Added `html.escape` and applied it to every patient-controlled value in the HTML bodies:

- `app/chat.py` fallback notification: session name, session email, question text.
- `app/pending.py` reply email: patient name, question text, reply text.

Subjects and plain-text bodies are unchanged.

## Files changed

- `app/chat.py`
- `app/pending.py`
- `tests/test_email_html_escaping.py`
- `docs/fixes/H-14.md`

## Tests

`tests/test_email_html_escaping.py` calls the real chat fallback handler and pending reply function with fake database connections, requests, and email senders; no network or database is used. It verifies that markup in names, email values, questions, and replies is escaped in the generated HTML and that the raw tags are absent.
