# H-15: Weak Email Validation Allows Relay to Arbitrary Addresses

- **Issue:** H-15 — email validation only checked for `"@" in email`
- **Severity:** High

## Root cause

`app/chat.py` and `app/pending.py` accepted any non-empty string containing `@` as an email address. Clinic replies could therefore be sent to malformed or arbitrary destinations, creating a spam/phishing relay.

## Fix

Added `app/validation.py` with one shared `is_valid_email` helper. It enforces:

- Overall length of at most 254 characters.
- A stdlib regex requiring a non-empty local part, a valid domain label, and at least one dotted domain suffix.
- Rejection of malformed forms such as consecutive dots, leading/trailing dots, and hyphen-edged domain labels.

`app/chat.py` now uses `is_valid_email(email)` in `create_session`, and `app/pending.py` uses it before sending a reply email.

The H-14 test fixture was updated to use a valid reserved-domain address because stricter validation now blocks its previous malformed fixture.

## Tests

`tests/test_email_validation.py` covers valid addresses, the 254/255 length boundary, missing domain suffixes, consecutive dots, leading dots, and hyphen-edged labels. It also verifies that chat rejects an `a@b` address before any database call and that pending replies do not send to it.

## Verification

Without the validation change in `app/chat.py` and `app/pending.py`:

```text
python -m pytest -q tests/test_email_validation.py
2 failed, 1 passed
```

With the fix and full suite:

```text
python -m pytest -q
49 passed in 1.48s
```
