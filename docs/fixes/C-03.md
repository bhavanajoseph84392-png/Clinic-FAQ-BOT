# C-03: Hardcoded Credentials

## What was wrong

- `migrations/006_rls.sql` created the `app_user` role with a literal password.
- `app/config.py` used literal fallback database URLs and a fallback session signing key.
- `scripts/seed_demo.py` contained a literal demo admin password and a literal webhook secret.
- `scripts/migrate.py` used a substring check for localhost-looking URLs instead of requiring real environment configuration.

The values were removed from Git history, but the source still contained the credentials and placeholders. No credential value is repeated in this document.

## What changed

- `migrations/006_rls.sql` now creates `app_user` without a password.
- `scripts/migrate.py` requires `MIGRATION_DATABASE_URL` and `APP_USER_PASSWORD`, then applies the role password with a parameterized `ALTER ROLE app_user WITH PASSWORD %s` after the migration files run.
- `app/config.py` requires `DATABASE_URL`, `MIGRATION_DATABASE_URL`, and `SECRET_KEY` at import time and raises a clear `RuntimeError` when one is missing. There are no fallback values.
- `scripts/seed_demo.py` requires `DEMO_ADMIN_PASSWORD` and `DEMO_WEBHOOK_SECRET` and exits with a message when either is missing.
- `.env.example` lists variable names with placeholder values only.
- `tests/test_secrets.py` scans every tracked file and fails if the removed placeholder text is found.

## Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Application connection string. Must use `app_user` with the password in `APP_USER_PASSWORD`. |
| `MIGRATION_DATABASE_URL` | Migration/owner connection string. |
| `APP_USER_PASSWORD` | Password applied to the `app_user` role during migrations. |
| `SECRET_KEY` | Session signing key. Use a long random value. |
| `DEMO_ADMIN_PASSWORD` | Demo seed admin password. Demo environments only. |
| `DEMO_WEBHOOK_SECRET` | Demo seed webhook secret. Demo environments only. |

## Set the variables locally

1. Create the local file:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Fill in `DATABASE_URL`, `MIGRATION_DATABASE_URL`, `APP_USER_PASSWORD`, and `SECRET_KEY`.

3. Generate a strong `SECRET_KEY`:

   ```powershell
   python -c "import secrets; print(secrets.token_hex(32))"
   ```

4. Set `DEMO_ADMIN_PASSWORD` and `DEMO_WEBHOOK_SECRET` only when running the demo seed.

5. Keep `.env` out of Git. It is already ignored.

## Set the variables on Render

1. Open the Render Dashboard and select the web service.
2. Open **Environment**.
3. Add `DATABASE_URL`, `MIGRATION_DATABASE_URL`, `APP_USER_PASSWORD`, and `SECRET_KEY`. Use the secret-value option for `APP_USER_PASSWORD` and `SECRET_KEY`; Render can generate `SECRET_KEY`.
4. Make sure the password in `DATABASE_URL` matches `APP_USER_PASSWORD`.
5. Add `DEMO_ADMIN_PASSWORD` and `DEMO_WEBHOOK_SECRET` only for demo environments.
6. Save and redeploy. The pre-deploy command runs `scripts/migrate.py`, which applies the role password from the environment.

If `render.yaml` currently injects a different database URL, update that deployment setting separately; do not commit credentials to the repository.
