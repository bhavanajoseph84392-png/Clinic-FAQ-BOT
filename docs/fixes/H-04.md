# H-04: Migration Script Uses CWD-Relative Path and No Transactions

- **Issue:** H-04 — migrations silently skipped outside the project root; no per-file transaction
- **Severity:** High

## Root cause

`scripts/migrate.py` found migrations with `glob.glob("migrations/*.sql")`, which depends on the current working directory. Running the script from another directory found zero files and still printed success. The connection also used `autocommit=True`, so a failed migration could leave earlier statements applied.

## Fix

- Added `MIGRATIONS_DIR` anchored to the script file: `Path(__file__).resolve().parent.parent / "migrations"`.
- Return `False`, which exits with status 1, when the directory contains no `*.sql` files.
- Removed `autocommit=True` and wrapped schema setup, each migration file, and the role update in `conn.transaction()`. Each migration file and its `schema_migrations` row now commit or roll back together.

The existing skip marker and environment checks are unchanged.

- `tests/test_migrate_script.py`

## Tests

`tests/test_migrate_script.py` loads the script directly and uses a fake `psycopg.connect`; no database is contacted. It verifies:

- From an empty temporary working directory, all repository migrations are still applied.
- At least one transaction is opened beyond the number of migration files.
- An empty migrations directory returns `False` without calling `connect`.

## ALTER ROLE fix

`ALTER ROLE` does not accept bound parameters, so the previous `%s` placeholder raised `syntax error at or near "$1"`. The role update now builds its statement with `psycopg.sql` and inlines the password as a validated literal.

- `scripts/migrate.py:4` imports `sql` from `psycopg`.
- `scripts/migrate.py:58-64` (inside the existing `conn.transaction()`) executes `sql.SQL("ALTER ROLE app_user WITH PASSWORD {}").format(sql.Literal(app_user_password))`, so no `%s` or `$1` placeholder is sent.
- `scripts/migrate.py:51-54` renames the local migration text variable to `migration_sql` so it no longer shadows the imported `sql` module.
- `tests/test_migrate_script.py:82-108` uses a fake cursor and asserts the `ALTER ROLE` statement is executed once with `params is None`, contains the escaped password literal `'s3cret''pw'`, and contains neither `%s` nor `$1`.

The password is never printed or logged. The test uses a fake connection only; no database is contacted.
