# H-05: Grounding Check Uses Substring Match

## What was wrong

`verify_grounding` treated any classifier reply containing the substring `"PASS"` as success. Replies such as `"NOT PASS"`, `"FAIL: the answer does not PASS"`, or `"PASSAGE NOT FOUND"` therefore passed the grounding check, allowing an ungrounded answer to be shown to the patient.

## Code evidence

Before the change, `app/rag.py:116`:

```python
    return "PASS" in result
```

The surrounding call already normalizes the reply with `.strip().upper()` at `app/rag.py:115`.

## What changed

`app/rag.py:116` now accepts only an exact `"PASS"` after the existing trimming and case normalization:

```python
    return result == "PASS"
```

Anything else returns `False`, including an empty reply. The rest of `verify_grounding` is unchanged. The grounding prompt at `app/prompts.py:22-23` already says "Respond with only PASS or FAIL", so it already matches the exact-match rule and was not changed.

## Test

`tests/test_grounding_strict.py` replaces `app.rag._call_gemini` with a fixed fake and makes no network or database calls. It asserts:

- `"PASS"` -> `True`
- `" pass \n"` -> `True`
- `"NOT PASS"` -> `False`
- `"PASSAGE NOT FOUND"` -> `False`
- `"FAIL"` -> `False`
- `""` -> `False`
