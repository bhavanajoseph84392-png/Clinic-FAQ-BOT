# C-06: Classifier Fails Open

## What was wrong

`classify_message` returned `"faq"` whenever the classifier output was empty, unrecognized, or the classifier call raised. `"faq"` is not a refusal: `answer_question` lets it continue to lesson lookup, retrieval, and answer generation. Uncertain or failed classifications could therefore be answered as ordinary questions instead of being refused or escalated.

## Code evidence

Before the change, `app/rag.py:86-99`:

```python
    classification = _call_gemini(
        system_instruction=CLASSIFY_SYSTEM,
        user_prompt=question,
        model_name=settings.CHECK_MODEL
    ).strip().lower()
    
    if "medical" in classification:
        return "medical"
    elif "smalltalk" in classification:
        return "smalltalk"
    elif "abuse" in classification:
        return "abuse"
    else:
        return "faq"
```

The classifier call at `app/rag.py:86-90` was not wrapped in exception handling, and the final `else` at `app/rag.py:98-99` returned `"faq"` for every value that did not match a known label.

## What changed

The fallback now returns the existing `"medical"` intent. A valid `"faq"` output is matched explicitly and still returns `"faq"`. An exception from the classifier call is caught and also returns `"medical"`.

```python
    try:
        classification = _call_gemini(
            system_instruction=CLASSIFY_SYSTEM,
            user_prompt=question,
            model_name=settings.CHECK_MODEL
        ).strip().lower()
    except Exception:
        logger.warning("Message classification failed; using safe fallback route.")
        return "medical"
    
    if "medical" in classification:
        return "medical"
    elif "smalltalk" in classification:
        return "smalltalk"
    elif "abuse" in classification:
        return "abuse"
    elif "faq" in classification:
        return "faq"
    else:
        return "medical"
```

`"medical"` was chosen because it is an existing route that already refuses and escalates: `answer_question` returns `fallback_res` for it (`app/rag.py:147-148`), and the chat handler records a Pending question when the fallback message is returned (`app/chat.py:65-67`). `"abuse"` also leads to the fallback, but its meaning is specifically detected abuse, so it was not used for undecidable output.

## Test

`tests/test_classify_fallback.py` replaces `app.rag._call_gemini` with a fake function and makes no network or database calls. It checks these cases:

- Empty classifier output returns `"medical"`.
- An unknown label returns `"medical"`.
- A raised exception returns `"medical"`.
- Each valid label (`faq`, `medical`, `smalltalk`, `abuse`) still returns itself.
